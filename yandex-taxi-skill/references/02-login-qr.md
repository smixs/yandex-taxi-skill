# 02. Вход по QR и безопасное сохранение state

Нужен вход один раз. Дальше работает сохранённый state (cookies).

## Вход
1. Режим: обычный. Если сайт режет headless, добавь `--headed`.
2. Открой `https://<TAXI_HOST>/`, нажми «Войти» → «QR-код». Кнопка иногда перекрыта: клик через `eval` по элементу.
3. Скриншот QR отправь владельцу (только ему): он сканирует приложением Яндекс/Яндекс Go. QR живёт минуты. Истёк - сделай новый.
4. Жди возврата на `<TAXI_HOST>`. Проверь, что вверху справа имя аккаунта (`ACCOUNT_NAME`), а не «Войти».
5. Сохрани: `scripts/yandex-taxi.sh state-save`.

## Что делает state-save
- Пишет во временный файл, не в рабочий.
- Проверяет: JSON читается, есть `Session_id` для домена yandex.
- Плохой новый файл - отказ, старый не тронут.
- Бэкап старого в `state.bak.json`, потом копия поверх, права 600, папка 700.

## Проверка в любой момент
`scripts/yandex-taxi.sh state-check [файл]` → «OK cookies=… Session_id_domains=… mode=600». Код 1 - плохой файл, 2 - права не 600 (`chmod 600`).

## Правила
- State лежит вне git, вне vault, вне общих папок. Не слать в чат.
- Не перезаписывай рабочий state, пока новый не прошёл проверку.
- Старые state от другого домена (.ru) для .uz не использовать.
- Вход слетел (`LOGIN_LOST`) = цены без входа другие («от …»), им не верить.
